# V8.84 Mobile UX and Quality Pass

## Included
- Tenant rent hero reads the latest saved EB and water bill-cycle shares for the signed-in tenant's house. Missing records are displayed as missing; charges are not guessed or silently added to rent due.
- Blueprint editor has a lightweight CSS isometric preview toggle. Flat editing remains the default.
- Rent approval cards use a higher swipe threshold before approve/reject actions. Reject remains an explicit reason-based flow.
- Open maintenance requests can be swiped right to mark them in progress. Resolve remains an explicit button to avoid accidental resolution.
- House share, announcement share and user settings dialogs use mobile bottom-sheet alignment and safe-area padding.
- MoreMenu already uses React.lazy/Suspense for its secondary modules; this behavior is retained, including TallyExport, YearEndSummary, DataBackup and BlueprintManager.
- Corrected toast calls to use the actual `useToast()` API (`showToast({ message, type })`) in RentApprovalQueue and YearEndSummary.
- Centralized EB/water split calculations in `src/utils/billSplit.js` while preserving service-level exports for existing imports.
- Added Node's built-in test runner and unit tests for bill-split eligibility and finite share amounts.
- Added mobile tap/overscroll CSS and reduced-motion handling for the isometric preview.

## Verification
- `node --test`: 2 tests pass.
- Production build: not verified in this environment because dependencies were unavailable (`vite: not found`); `npm ci` did not complete within the available execution window.
- Live Firestore behavior, Android WebView behavior and payment/approval workflows must be tested in a staging deployment before production rollout.

## Important limitations
- The EB/water breakdown displays the latest saved share record for each service, not necessarily a bill for the current calendar month. It does not combine bill shares into rent due.
- The isometric view is a CSS preview, not a true navigable 3D building model; floor stacking and pinch-to-zoom are not included.
- Approval swipe right approves only after a deliberate threshold; swipe left opens the existing rejection flow. Review the confirmation/reason behavior on a staging account.
