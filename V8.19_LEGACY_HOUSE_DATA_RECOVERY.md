# V8.19 — Legacy House Data Recovery

Fixes a data-visibility regression introduced by propertyId-scoped house queries.

## Problem
Older `houses` documents created before the multi-apartment security boundary may not have a `propertyId` field. A query `where('propertyId', '==', 'default')` cannot return those documents, so Owner Home/Tenants could show zero houses even though the data still exists.

## Fix
- Keep the normal property-scoped query as the fast path.
- For the default apartment, admin users and legacy owners without `propertyAccess` may safely read the collection and recover records missing `propertyId`.
- Missing `propertyId` is treated as `default` in memory; records are not silently rewritten.
- Restricted co-owners remain on property-scoped queries.
- `listAllHouses()` also includes legacy unassigned records when the user is allowed to read all properties.

This preserves the V8.10 Firestore security boundary while restoring visibility of pre-migration data.
