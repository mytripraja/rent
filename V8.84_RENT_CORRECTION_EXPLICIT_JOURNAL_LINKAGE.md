# V8.84 — Rent correction uses explicit journal linkage

- Rent correction now prefers `paymentId` and `approvalJournalId` links added by V8.83 rather than relying on house/description/amount matching.
- If a payment references linked journal entries but they are missing or incomplete, correction stops for manual review instead of falling back to ambiguous legacy matching.
- Legacy payments without explicit linkage retain the prior guarded matching path.
- Transaction revalidation now also checks house/property scope and the payment link when present.
- Replacement payments and their journal lines now carry explicit payment/journal linkage, so a later correction can find them reliably.

Validation: JavaScript syntax and ZIP integrity checks passed. Full Vite build, live Firestore, and concurrent correction tests were not performed.
