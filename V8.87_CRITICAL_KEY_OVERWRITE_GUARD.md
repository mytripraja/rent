# V8.87 — Critical key overwrite guard

- The `set` action now only permits initial configuration when no critical-key hash/salt exists.
- The check and write run in a Firestore transaction to prevent concurrent setup requests from overwriting one another.
- Existing keys can be changed through the existing email-confirmed reset flow.
- Settings UI no longer presents the unauthenticated direct-set form after configuration.
- Existing user records and key material are not migrated or cleared.

Validation: `node --check api/rental.js` and ZIP integrity check. Full Vite build and live Firestore testing were not performed.
