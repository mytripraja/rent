# V8.43 — Firebase Leakage & Security Hardening

## Fixed
- Tenant access to `houses/{houseId}` is removed from Firestore. Tenant-safe house data is returned through a server endpoint with field allow-listing. Rent/advance/owner-only fields are not exposed when rent details are disabled.
- `rentStatus`, `rentDetails`, and `rentSubmit` now honor the `rent` master switch in Firestore rules.
- Targeted notices are now readable only by tenants whose own house is included, or by notices explicitly targeted to all houses.
- Directory reads are property-scoped in both the client query and Firestore rules.
- Restricted co-owners can only change tenant permissions for tenants whose house belongs to a property they can access.
- Family-account owner APIs now enforce the caller's property access before create/list/update/delete and roll back newly created Auth users if Firestore setup fails.
- Payment proof uploads (rent, EB, water) and maintenance photos now use server-signed Cloudinary uploads with authenticated delivery. The upload endpoint enforces tenant permissions and house ownership.
- The server forces authenticated Cloudinary delivery for sensitive proof/maintenance folders even if a client asks for public delivery.
- Public-facing/owner uploads such as notices, expenses, house photos, tenant photos and profile photos now go through the server signing endpoint instead of an unrestricted unsigned upload preset.
- Payment proof viewing uses short-lived owner-authorized signed URLs for newly protected proofs. Legacy public `proofUrl` records are not re-signed.

## Audit findings
- Firebase web configuration values (`apiKey`, project ID, app ID) are client configuration, not service-account secrets. No service-account private key or Cloudinary secret was found in the shipped source.
- App Check remains configurable through `FIREBASE_APPCHECK_ENFORCED`; production should keep this enabled after the registered reCAPTCHA Enterprise site key is verified.
- `appConfig` is still readable by signed-in users because resident screens currently consume shared operational configuration. It does not currently contain service-account credentials, but secrets must never be placed in this document.
