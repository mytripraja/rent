# V8.92 — Rent submission rules hardening

- Tightened the tenant-side `rentPayments` create rule so client validation is backed by Firestore security rules.
- Requires an exact allowed field set and required fields; blocks unexpected client-supplied fields.
- Enforces the signed-in tenant's own house and UID, waiting-approval state, positive bounded amount, month/date formats, supported payment modes, and mode-specific cash/neighbor fields.
- Restricts the recorded-by object and proof metadata shape. Owner-created manual entries retain the existing owner-access path.

Limitations: Firestore rules validate the date's string format but not calendar validity (for example, February 31). They also cannot verify that an uploaded proof asset belongs to the caller. The existing private-upload and signed-URL authorization flow remains responsible for document access. Rules emulator and live Firestore tests were not run in this environment.
