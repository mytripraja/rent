# V8.93 — Rent approval action feedback and duplicate-click guard

- Added a synchronous in-flight lock around approve/reject mutations so rapid clicks or overlapping UI actions do not start duplicate requests from the same queue instance.
- Disabled queue action buttons while a mutation is running and show a working label for the selected payment.
- Surface the actual operation error message when available, including stale-status and transaction validation messages, instead of replacing every failure with a generic toast.
- Kept the existing Firestore transaction as the source of truth; this UI guard is supplementary and does not replace server/security enforcement.

Validation: source-level checks and ZIP integrity only. Full Vite build and live Firestore/concurrency tests were not run because dependencies and a test project are unavailable in this environment.
