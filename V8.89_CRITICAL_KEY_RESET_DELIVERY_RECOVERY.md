# V8.89 — Critical-key reset delivery recovery

- If the reset email provider returns a non-success response, the endpoint clears the undelivered reset-code state.
- Cleanup is transaction-backed and only clears the request whose timestamp matches the failed delivery, preserving any newer request.
- The error message now invites the user to request a fresh code instead of imposing a cooldown for an email that was not delivered.
- Existing critical-key hashes and user records are preserved; no migration is required.

Validation: JavaScript syntax check and ZIP integrity check. Provider failure behavior and live Firestore concurrency were not tested.
