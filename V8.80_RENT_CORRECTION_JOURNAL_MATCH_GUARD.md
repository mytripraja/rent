# V8.80 — Rent correction journal matching guard

- Removed the heuristic that selected the two newest matching journal lines.
- Correction now requires exactly two journal lines matching the house, rent month, amount, and full approval description.
- If the original journal cannot be identified unambiguously, the API returns HTTP 409 before changing the payment.
- This is a safety guard, not a complete atomicity fix: payment status, reversal, replacement entries, and audit logging are still separate writes. A follow-up should migrate journal linkage to explicit payment IDs and make the correction workflow transactional/idempotent.
