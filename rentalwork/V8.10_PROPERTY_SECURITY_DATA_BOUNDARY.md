# V8.10 — Property Security & Data Boundary

## Updates
- Enforced property-scoped owner access for houses and parking records.
- House listing now queries Firestore by `propertyId` instead of downloading all houses and filtering in the browser.
- Multi-property house listing queries only configured property IDs.
- House assets, inspections and history inherit the parent house's property access.
- Existing apartment/ERP property-level rules remain in place.
- New house creation persists `propertyId` and is validated by rules.
- Cross-apartment house moves are permitted only when the owner has access to both source and destination properties.
- This reduces data exposure and improves performance for restricted co-owner accounts.

## Migration note
Existing houses created before property IDs were introduced may need a one-time assignment to the `default` property (or their real apartment) before restricted co-owner accounts can see them.
