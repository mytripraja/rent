# V8.18 — Firestore Index Resilience

## Problem fixed
Production screenshots showed Firestore `The query requires an index` failures on the Owner overview, Tenants, and EB bill screens.

## Changes
- `rentService.listRentHistory()` now queries by `houseId` only and sorts `submittedAt` in JavaScript.
- `houseService.listHouses()` and `listAllHouses()` now query by `propertyId` only and sort door numbers client-side.
- `ebBillService.listEbBillCycles()` avoids `array-contains + orderBy` and sorts client-side.
- EB payment history avoids `houseId + orderBy` composite queries.
- Water bill cycle/payment history avoids the same composite-query pattern.
- Communication logs, resident documents, enterprise field lookups, and advance ledger history avoid `where + orderBy` composite queries where the filter is already sufficient.

## Result
These paths no longer depend on manually-created Firestore composite indexes for their normal list views.

## Validation
- ZIP integrity verified.
- Source-level query scan performed for remaining `where + orderBy` patterns.
- Full Vite production build was attempted but dependency installation timed out in the build environment, so no claim of a complete production build is made.
