# Rental Manager V8.58 — Firestore Rules Syntax & Security Fix

## Critical fix

The V8.57 `firestore.rules` file contained an invalid Firestore Rules expression in `canAccessUserRecord()`. The expression attempted to call `recordPropertyId(get(...).data)` inside a `hasAny([...])` list, which caused the Firebase Console parser error at line 113 and a cascading error near the end of the rules file.

The expression was replaced with the existing `canAccessHouse(data.houseId)` helper. This preserves the intended property boundary while using a rules expression already used elsewhere in the ruleset.

## Result

- Restricted co-owners still only access tenant user records belonging to houses in their assigned properties.
- Admins and unrestricted legacy owners retain their existing access.
- No data migration or deletion.
- The trailing `unexpected '}'` error was a cascade from the earlier parse failure; the brace structure itself was not changed.

## Verification

- All plain JavaScript files checked with `node --check`.
- `firestore.rules` inspected around the reported line and the complete match/brace structure.
- Firebase CLI/rules compiler was not available in the execution environment, so a live Firebase rules publish was not claimed.
