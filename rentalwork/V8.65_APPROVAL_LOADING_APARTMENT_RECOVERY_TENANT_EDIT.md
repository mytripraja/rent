# V8.65 — approvals, apartment recovery, tenant login and editing

- Pending approvals display a loading state and errors instead of a false empty message while fetching.
- Login setup generates a Firebase password reset link without an undefined continue URL. An optional configured continue URL must be HTTPS and authorized in Firebase Authentication. Email delivery still requires RESEND_API_KEY and EMAIL_FROM.
- Owners can edit the current tenant’s name, phone, email, move-in date, approximate flag, and EB number. Server verifies tenant-house binding and property access, updates tenant profile and house, and updates the directory without exposing hidden phone numbers.
- Apartment registry recovery checks both legacy `properties` records and property IDs on houses. Does not invent missing apartments without persisted evidence; no live database access was available.
- No new Vercel function; existing Firestore collection permissions remain in place. Deploy firestore.rules if your production rules are older than the project.

## Critical deployment root cause
V8.64 `.vercelignore` excludes `api/app-config.js` but `vercel.json` had no rewrite for `/api/app-config`. The app silently fell back to one default apartment. V8.65 routes `/api/app-config` through the existing `/api/rental` function and bundles the handler from `lib/appConfigHandler.js`. This retains the 11-function Vercel Hobby budget. The apartment switcher shows a retryable error rather than silently replacing persisted properties with a default.

- Tenant editing also includes monthly rent. This updates future house rent only; past payment records are untouched.
