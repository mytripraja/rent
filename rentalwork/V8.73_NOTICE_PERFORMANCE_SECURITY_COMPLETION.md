# Rental Manager V8.73 — Notice, Approval & Security Completion

## Main fixes
- Rent Approval no longer waits for a separate full house-list query. The server queries only waiting approvals, resolves only their referenced houses, applies the property boundary, and returns minimal house context with each approval.
- Approval UI shows the approval list as soon as approvals arrive; app configuration/late-fee data loads independently.
- Notices now support local search by title, content, category, date, year and weekday.
- Each notice has a Details view showing the complete record and creation timestamp.
- Expected resolution cannot be earlier than Started / happened; Resolved at cannot be earlier than Started or Expected resolution. The same validation is enforced in the service layer.
- Public announcement pages now use the consolidated rental API route, avoiding Vercel Hobby function-count problems, and display creation date.
- News Hub is removed from family/subtenant permissions and is no longer exposed through the Vercel deployment allow-list.
- Wi-Fi sharing terms upgraded to V3 with explicit ISP authorization, lawful-use, privacy, credential, security and responsibility language; legacy V1/V2 records remain compatible.
- Tamil notice translation adds more complete sentence patterns for common EB/water/maintenance updates while retaining manual Tamil editing.

## Preserved
- Property-scoped Firebase access and legacy house fallbacks.
- CCTV camera-to-house and house-to-camera mapping, covered places and privacy acknowledgement.
- Rent increase history and future effective month.
- Initial/additional advance ledger.
- Household member editing with age bands and gender.
- House room layout and fixture/equipment history.
- Secure rent correction protected by the separate critical-change password and supported device biometric/passkey flow.
- Announcement continuation and multi-link/disconnect workflow.

## Verification
- Plain `.js` files were syntax-checked with Node.
- Vite production build could not be completed in this environment because dependency installation timed out and the local Vite executable was unavailable. Do not claim a successful build until Vercel/local `npm run build` passes.
- Firestore rules were source-reviewed; Firebase CLI was not available for a rules deployment check.
- CCTV privacy controls now use policy V2 for new saves, include a planned retention-days field, and require a privacy acknowledgement plus bounded retention value in Firestore rules; legacy V1 cameras remain readable.
