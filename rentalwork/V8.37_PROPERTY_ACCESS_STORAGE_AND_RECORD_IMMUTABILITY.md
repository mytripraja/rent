# V8.37 — Property Access Storage & Record Immutability

## Changes
- Resident-document signed URLs now accept a Firestore document ID and resolve the Cloudinary asset server-side. The endpoint checks the caller's owner/admin role and property access before signing.
- The resident-document signer rejects arbitrary Cloudinary public IDs and only signs assets stored under `private-documents/<houseId>/`.
- CCTV private-copy viewing now uses a dedicated server endpoint keyed by the `cctvFootageRequests` record ID. The endpoint checks property access before signing and rejects arbitrary Cloudinary IDs.
- House-linked records keep `houseId` immutable during authorized updates for rent payments, EB/water payments, documents, maintenance, visitors, rent agreements, advance-ledger entries, and common-area bookings. Delete permissions remain separate so delete requests do not depend on `request.resource`.
- Existing application records are preserved. No data migration is required.
