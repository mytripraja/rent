# Rental Manager V8.49 — Property-scoped billing & communication hardening

## Fixed
- Added `propertyId` to EB and water bill cycles. Restricted co-owners now read/write only the selected property.
- Added `propertyId` to notices and complaints. Restricted co-owners cannot directly create/read/update/delete another property's communication records.
- Tenant complaint creation carries the tenant property boundary.
- EB/water owner list queries now filter by the active property instead of broad collection reads.
- Existing records without `propertyId` remain available to admin/unrestricted legacy owners; restricted owners do not gain access to unscoped legacy records. Tenant-specific billing/communication access remains intact.

## Security intent
Property access is enforced in Firestore rules as well as in the UI. Client-side apartment selection is not treated as the security boundary.

- New primary/family tenant profiles now retain the house `propertyId`, allowing tenant-originated complaints to keep the same server-side boundary.
