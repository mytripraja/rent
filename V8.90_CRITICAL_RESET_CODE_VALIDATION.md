# V8.90 — Critical reset code validation

- The server now validates reset codes as exactly six numeric digits before running the password-hash comparison.
- The Security Settings reset UI validates the same format, disables invalid submissions, and prevents duplicate reset/confirm requests while an action is in progress.
- Starting a fresh reset request clears any code left in the form.
- Existing critical-key hashes and user records are preserved; no migration is required.

Validation: JavaScript syntax checks and ZIP integrity check. Full Vite build and live email/Firestore tests were not run because dependencies and production services were unavailable in this environment.
