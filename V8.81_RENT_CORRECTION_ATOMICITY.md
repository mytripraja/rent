# V8.81 — Atomic rent correction

- Moved the payment status update, reversal journal lines, optional replacement payment and its journal lines, and correction audit record into one Firestore transaction.
- Revalidates the approved payment and source journal lines inside the transaction before writing.
- Uses deterministic correction/reversal/audit document IDs to prevent repeated requests from creating duplicate correction artifacts.
- If any write fails, the transaction aborts instead of leaving only part of the correction applied.

## Validation limits

- JavaScript syntax and ZIP integrity checks were run.
- No live Firestore integration, concurrency, or production build test was run in this environment.
- Legacy journal matching still relies on the exact description and amount; explicit historical payment-to-journal linkage remains future work.
