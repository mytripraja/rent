# V6.9 — Multi-apartment operations

## Separation
- Added apartment/property operations workspace.
- Each apartment has its own `propertyId` for motors, tanks, problem history, CCTV cameras and footage records.
- Houses can be assigned to an apartment; legacy houses without a `propertyId` remain under the default property until moved.
- The existing property switcher and the new Apartment Operations selector both switch the active apartment.

## Water and motors
- Configurable motors per apartment: bore, sump, or other.
- Configurable target reading and unit (kW/V/HP/A), tolerance and retry window.
- Start command checks the configured target. If outside range, start is blocked and a retry command is recorded for the configured 5–10 minute window.
- Starting a sump motor automatically records an interlock stop for an already-running bore motor.
- Configurable tanks with capacity, fill time for each motor and cleaning history fields.
- The UI records control commands; actual physical switching requires a connected relay/IoT controller. No fake hardware control is claimed.

## Problem history
- Per-apartment and per-house problem records.
- Category, severity, occurrence time, duration, recurrence, root cause, action taken, follow-up date and notes.
- Future-warning flag makes recurring/early problems easier to find before they become major issues.

## CCTV
- Per-apartment/per-house camera records with location, direction, NVR/main-box location, username, purchase date and warranty duration.
- Warranty remaining time is calculated automatically from purchase date + warranty months.
- Raw CCTV passwords/patterns are deliberately not stored in ordinary Firestore notes. A secure password-manager/vault reference field is provided instead.
- Footage requests record requester, date/time range, purpose, whether a copy was taken, and the stored private copy.
- Uploaded footage uses the existing authenticated Cloudinary upload flow and owner-only short-lived signed viewing URLs.

## Security
- New Firestore collections are owner-only and use `propertyId` records to keep operational data separated.
