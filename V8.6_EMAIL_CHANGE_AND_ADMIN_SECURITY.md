# V8.6 — Secure Email Change + Admin Review

## Email change workflow

A signed-in user can open **Settings → Account & Email → Change email address**.

### If the old email is accessible
1. Enter the new email.
2. Rental Manager sends one 6-digit OTP to the old email and a separate OTP to the new email.
3. User enters both OTPs.
4. Server verifies both hashes and updates Firebase Auth + `users/{uid}`.
5. Tenant customer/house/directory records are synchronized when applicable.
6. An audit entry is created.

OTP values are never stored in plaintext. They are salted SHA-256 hashes and expire after 10 minutes. Each code has a maximum of five failed attempts.

### If the old email is inaccessible
1. User checks **I cannot access my old email**.
2. User enters a reason.
3. No OTP is accepted as proof; the request becomes `pending_admin`.
4. Admin opens **More → Owner Management → Email change requests**.
5. Admin reviews the old/new email, role and reason.
6. Admin can approve or reject.
7. Approval changes Firebase Auth and the app profile server-side without requiring the old-email OTP.

## Required email provider configuration

The secure OTP workflow needs an email provider. This implementation uses the Resend HTTP API from the existing Vercel serverless endpoint, so no new serverless function is required.

Configure:

- `RESEND_API_KEY`
- `EMAIL_FROM` using a verified sender/domain in Resend

Do not put the Resend key in `VITE_*` variables or client-side code.

## Existing tenant-contact path

The existing owner-level tenant contact endpoint remains available for controlled admin/owner tenant edits. The new self-service workflow is separate and uses the same already-allowed Vercel function to avoid increasing the serverless-function count.
