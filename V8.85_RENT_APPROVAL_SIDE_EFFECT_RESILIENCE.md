# V8.85 — Rent approval side-effect resilience

- Keeps the rent payment status and its two accounting journal lines in the existing Firestore transaction.
- Makes post-transaction tenant notification and activity logging best-effort, matching the rejection flow. A failure in either no longer reports the already-committed approval as a failed action.
- Allows legacy house records without an explicit `propertyId` to use the existing `default` property fallback when creating journal entries.
- No migration or destructive data changes are required.

Validation: source syntax checks only; no live Firestore or full Vite build test was performed.
