# V7.0 — Apartment switching, access, device security & notifications

## Apartment workspace
- Mobile and desktop apartment switcher is visible in the owner header.
- Apartment Operations now has a simple New apartment button and a current-apartment summary.
- Apartments remain separate by property ID.
- Owner creation asks whether the new owner can access all apartments or selected apartments.
- Existing owner profiles without `propertyAccess` remain backward-compatible and are treated as all-access.

## Device unlock
- Optional local device lock in Settings.
- PIN lock uses a salted SHA-256 hash; the PIN is not stored as plaintext.
- Fingerprint/face/device passkey uses WebAuthn platform authentication. Biometric data is never sent to Rental Manager.
- Device lock protects a signed-in session after refresh/relaunch; it does not replace Firebase authentication.

## Authenticator MFA
- Settings includes optional TOTP Authenticator-app enrollment.
- Supports Google Authenticator, Microsoft Authenticator, Authy and compatible TOTP apps.
- Login handles Firebase `auth/multi-factor-auth-required` and prompts for the 6-digit code.
- Firebase Authentication with Identity Platform must have TOTP MFA enabled for the project.

## Notifications
- Settings has per-user switches for in-app, browser, rent, messages, maintenance and general notifications.
- Admin App Settings has a monthly unpaid-rent reminder schedule per occupied house.
- Each rule stores house, day of month, India time, enabled state and property ID.
- Existing GitHub Actions scheduler calls the secure endpoint every 15 minutes and the server sends one notification per house/month when the rent is still unpaid.
- The scheduler uses `REVOKE_CRON_SECRET` and never trusts a client-side schedule execution request.
