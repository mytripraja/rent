# V8.82 — Rent correction journal balance validation

Rent correction now requires the legacy source journal to resolve to exactly one balanced two-line pair: Cash / Bank debit and Rental Income credit, both equal to the payment amount and sharing a non-empty journalId. The transaction revalidates each source line's journal ID, account, debit, credit, description, and amount before writing reversals. Ambiguous, incomplete, or unbalanced source journals are rejected without correction writes.

This is a defensive validation improvement. It does not add explicit payment-to-journal linkage, and it does not constitute a live Firestore or production build test.
