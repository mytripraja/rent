# Rental Manager V8.57 — Security Audit, Document Privacy Regression Fix & Family Login Hardening

## Changes
- Restored the V8.55 tenant-document metadata boundary that was accidentally regressed in the V8.56 base: tenants can only read their own document metadata.
- Restored the index-resilient tenant document query using a single `tenantId` filter plus local `houseId` filtering.
- Family/sub-tenant account creation no longer accepts, transmits, stores, or exposes a temporary password.
- Family account creation now creates the Auth identity without a supplied password and sends a secure password-setup email through the existing Resend configuration.
- Added `propertyId` to family-account profiles for consistent property scoping.
- Expanded family-account permission management to include the newer rent, blueprint, calendar, news, family, and service-contact controls.
- Added family-account creation audit records.
- Fixed the legacy duplicate `api/create-subtenant.js` implementation so it follows the same secure password-setup workflow and no longer references an out-of-scope `houseSnap`.

## Data safety
- No existing houses, tenants, payments, bills, documents, or property records are deleted or migrated.
- If family login email delivery is unavailable, account creation is rolled back instead of leaving an unusable credential behind.

## Verification
- All plain JavaScript files checked with `node --check`.
- Firestore document-rule regression checked.
- Targeted family-account and tenant-document source checks passed.
- Full Vite production build could not be completed because the extracted environment does not contain a usable Vite installation; no successful build is claimed.
- Family-account create/list now use a single `houseId` Firestore filter and local role filtering, avoiding an unnecessary composite index requirement.
- Family-account deletion now decrements the current house counter transactionally instead of relying on a stale/missing counter field in the user profile.
