# Rental Manager V8.54 — Document Upload Permission & Metadata Hardening

## Changes

### 1. Tenant private-document upload now requires the Documents permission
`api/sign-upload.js` previously allowed a tenant to obtain a Cloudinary upload signature for `private-documents/{houseId}` as long as the house matched the tenant's `houseId`. The later Firestore write could still be denied by rules, leaving an unnecessary orphaned Cloudinary asset.

V8.54 requires `tenantPermissionEnabled(profile, 'documents')` before issuing that upload signature.

### 2. Tenant document metadata is bound to the authenticated tenant
`firestore.rules` now requires a tenant creating a document record to use their own UID as `tenantId`.

This prevents a tenant from writing document metadata that falsely attributes the upload to another user in the same house.

### 3. Document ownership metadata cannot be changed during an owner update
Document updates keep both `houseId` and `tenantId` immutable. Owners can still update verification/expiry/re-upload fields, but cannot silently reassign the document to another tenant through a normal update.

## Preserved
- Owner/admin property access rules.
- Tenant access limited to their own house.
- Private Cloudinary authenticated delivery and short-lived signed URLs.
- Legacy documents remain usable.
- Existing document verification workflow remains unchanged.
