# V8.48 — Settings Save Fix + Property-Scoped UX + Advance Ledger Permission

## Fixed

- Fixed App Settings UPI and late-fee Save buttons: they now save the global configuration through the authenticated `/api/app-config` boundary instead of incorrectly saving only apartment details.
- Restricted co-owners no longer see global UPI, late-fee, or cash-receiver settings that they are not authorized to change. They continue to manage their assigned apartment details and reminder rules.
- Fixed an apartment-selection edge case where a restricted owner had an old/inaccessible `activePropertyId` in local storage. Settings now falls back to the first apartment actually returned for that user.
- Tightened `advanceLedger` tenant reads so the tenant needs both `rent` and `rentDetails` permissions, matching the intended tenant-permission model.

## Preserved

- Admin/unrestricted owner configuration access.
- Server-side app-config write boundary from V8.47.
- Property access isolation and legacy/default property fallback.
- Existing tenant login/password separation.

## Verification

- 76 JavaScript files passed `node --check`.
- Targeted source assertions passed for the settings write path, scoped-owner UI, version, and advance-ledger rule.
- No direct `appConfig` Firestore read/write remains in `src`; reminder rules continue through the authenticated server endpoint.
- `npm ci --ignore-scripts --no-audit --no-fund` was attempted but timed out in this environment, so a full Vite production build is **not claimed** for this release.
