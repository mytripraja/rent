# Rental Manager V6.8 — Access, Accessibility & Security Hardening

## Fixed in this release

- Added Vercel SPA history fallback so `/owner`, `/tenant` and nested React Router URLs survive a browser refresh instead of returning Vercel `404 NOT_FOUND`.
- Added security response headers (HSTS, no-sniff, frame protection, strict referrer policy, microphone/camera permissions and safe Google popup handling).
- Removed the persistent onboarding/welcome `?` button from owner and tenant headers.
- Expanded Accessibility Settings with larger text, high contrast, reduced motion, strong keyboard focus, page reading, reading controls and keyboard/screen-reader guidance.
- Added browser voice control for navigation and page reading. English and Tamil command examples are included.
- Added explicit Google Assistant and Alexa account-linking setup cards. These do not claim a service is linked until the required OAuth/Android/Alexa configuration exists.
- Expanded desktop tenant layout from a narrow 4xl column to a responsive 7xl workspace so desktop screens use the available width.
- Added server-side three-attempt login guard: wrong password → 2 attempts left → 1 attempt left → temporary 15-minute lock. Successful login clears the guard.
- Added IP-scoped rate limiting for Customer ID lookup and login guard requests.
- Added optional Firebase App Check using reCAPTCHA Enterprise. It can protect Firebase services and the Vercel API once configured and enforced.
- Tightened Firestore `users/{uid}` updates so owner-level accounts may only change `tenantPermissions` on tenant profiles; they cannot alter tenant role, house, name or other protected fields through that path.

## Important production security setup

### 1. Firebase Authentication

In Firebase Console → Authentication → Settings:

- Enable Email Enumeration Protection.
- Configure a strong password policy: at least 12 characters is recommended for this application, with upper/lowercase, number and non-alphanumeric requirements.
- Consider upgrading to Google Cloud Identity Platform and enabling MFA for owner/admin accounts.
- Keep end-user account creation disabled if all tenant accounts are created by property administrators.

### 2. Firebase App Check

1. Register `rent.deepusiva.com` in Firebase App Check using reCAPTCHA Enterprise.
2. Put the public site key in Vercel as:
   `VITE_RECAPTCHA_ENTERPRISE_SITE_KEY`
3. Deploy and verify App Check metrics first.
4. Then set:
   `FIREBASE_APPCHECK_ENFORCED=true`
5. Redeploy.

Do not enable enforcement before the production site is sending valid App Check tokens.

### 3. Vercel Firewall / WAF

The application now adds security headers, but the Vercel Firewall is controlled at the Vercel project level and cannot be fully configured by a frontend ZIP alone.

Recommended Vercel rules:

- Rate-limit `/api/*` abuse.
- Challenge or deny obvious automated login abuse.
- Monitor repeated 401/403/429 responses.
- Keep the firewall in front of the application and APIs.
- Review Vercel logs after enabling the rules.

### 4. Server secrets

Never put these in `VITE_` variables:

- `FIREBASE_SERVICE_ACCOUNT_KEY`
- Cloudinary API secret
- OAuth client secrets
- Alexa client secret
- Google OAuth client secret

### 5. Voice security

Browser voice control only navigates the already-authenticated app. A future AI voice agent must call the same authenticated APIs and tenant permission checks as the normal UI.

Alexa and Google account linking must use OAuth 2.0. Never send Firebase passwords to a voice provider.
