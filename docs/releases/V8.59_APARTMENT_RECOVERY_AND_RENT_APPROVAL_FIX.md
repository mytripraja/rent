# Rental Manager V8.59 — Apartment Recovery & Rent Approval Visibility

## Problem
An apartment created in an older release could remain represented by property-scoped
house/payment records while its `appConfig/general.properties` registry entry was
missing. The current property switcher then showed only the remaining registered
apartment. Rent approvals also appeared empty because the approval queue correctly
loads payments for houses belonging to the active apartment.

## Fix
- Admin and unrestricted legacy owners now get a one-time property registry recovery.
- Missing non-default property IDs are discovered from existing house records.
- Missing properties are restored into `appConfig/general.properties` with a clearly
  labelled recovery name so the apartment is selectable instead of silently hidden.
- Restricted co-owners do not receive this discovery path; `propertyAccess` remains
  the security boundary.
- Once the recovered apartment is selected, `listHouses()` supplies its houses to
  the existing property-scoped rent approval queue, so waiting rent submissions
  become visible again.
- No houses, tenants, payments, rent history, bills, or other records are deleted.
- The user can rename the recovered apartment later from Apartment Settings.

## Verification
- JS syntax checks performed on all `.js` files.
- Targeted checks cover the recovery branch and rent approval service.
- Firestore rules from V8.58 are preserved.
- Full Vite build is only claimed if `npm install`/`npm run build` succeeds in the
  available environment.
