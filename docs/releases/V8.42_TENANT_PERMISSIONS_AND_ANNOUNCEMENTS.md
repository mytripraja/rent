# V8.42 — Tenant Permissions + Detailed Announcements

## Tenant access controls
- Added separate `rentStatus`, `rentDetails`, and `rentSubmit` controls while preserving the legacy `rent` master switch.
- `rentSubmit` is enforced in Firestore, so disabling it blocks tenant payment creation even if a hidden UI is bypassed.
- Status-only tenants use a server-side status endpoint and do not receive direct rent payment history documents.
- Existing tenants without the new fields remain enabled for backwards compatibility.

## Announcements
- Expanded Notices into detailed incident announcements: title, category, message, affected houses, start time, expected resolution, resolved time, reason, additional details, and optional image.
- Target either all houses or selected houses. Targeted notifications remain house-specific.
- Added secure public share links using a per-notice random token; public pages expose only announcement details and affected door numbers.
- Added share formats: text, image, and PDF. Channels: WhatsApp, email, native device share, copy/download.
- Existing notices can receive a public share token when the admin opens Share.

## Security/data safety
- No tenant password workflow was changed.
- Existing property access boundaries remain intact.
- Existing rent, tenant, house, payment, and notice data is preserved.
