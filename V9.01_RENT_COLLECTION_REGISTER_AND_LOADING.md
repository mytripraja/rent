# V9.01 — Rent collection register and faster month navigation

- Reworked the owner Reports destination into a rent collection register as the default view.
- Shows house/door, tenant, month rent due, approved amount, paid/partial/waiting/unpaid/vacant status, and available payment metadata including method, reference, submitted/approved date, rejection reason, and recording/collection details.
- Added month picker and previous/next month controls, search by door/tenant/phone/house ID, status filters, and print support.
- The register loads its scoped house/payment/occupancy-history data once when opened. Changing the month filters the loaded data locally instead of repeating the network reads, making month-to-month navigation much faster.
- Preserved the prior full monthly financial report behind the “Full financial report” action.
- No rent/payment/house records are written or migrated by this read-only register.

Verification limits: dependencies were unavailable in the environment (`vite` missing; npm install could not complete), so a Vite production build and live Firestore performance test could not be run. Validate in the project environment before deployment. Initial register loading still depends on the size of the house/payment history; this update specifically avoids repeating those reads on each month change.
